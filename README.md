# Search as code: разговорный поиск товаров

Демо разговорного ассистента для поиска товаров. Одна реплика уходит двум агентам:

- **обычный агент (tool calling):** LLM в цикле вызывает инструменты — `search`, `semantic_search`, `get_product`, `check_product`… — и сама читает каждую карточку товара; кандгены — BM25 и одновекторный ANN;
- **search as code:** оркестратор пишет одну короткую программу на DSL (подмножество Python), runtime её исполняет и возвращает модели только сводку; кандгены — дообученный двухбашенный энкодер, многовекторный MaxSim (ColBERT-векторы BGE-M3), поиск по фото (SigLIP2), дообученный кросс-энкодер, QA-постфильтр по составу.

Каталог — российская часть [Open Food Facts](https://world.openfoodfacts.org) (ODbL, фото CC BY-SA): ~33,6 тыс. товаров с названиями, 22 тыс. фото. Цены и история покупок синтетические.

## Результаты

**Агенты** (Qwen3-30B-A3B, 20 одиночных запросов, судья — та же модель): search as code тратит в 4 раза меньше токенов на запрос (1,8 тыс. против 7,2 тыс.), оценка судьи 3,6 против 3,05. Разница по судье на 20 запросах статистически не значима (p≈0,3).

**Кандгены** (452 тестовых запроса, разметка 0/1/2 учителем Qwen3-30B, nDCG@10):

| Метод | nDCG@10 | Recall@50 |
|---|---|---|
| BM25 | 0,450 | 0,466 |
| Dense BGE-M3 (обычный ANN) | 0,514 | 0,556 |
| MaxSim (многовекторный), без дообучения | 0,535 | 0,534 |
| Dense, дообученный двухбашенный | 0,721 | 0,689 |
| MaxSim, дообученный | 0,711 | 0,671 |
| Гибрид двух дообученных | **0,731** | **0,713** |
| Поиск по фото (SigLIP2) | 0,350 | 0,240 |

Ранкер bge-reranker-v2-m3: 0,60 → 0,82 после дообучения. Оговорка: разметку для обучения и теста делал один и тот же учитель.

## Структура

- `app/` — приложение (FastAPI) и интерфейс: живое сравнение `/`, метрики `/metrics`, автотур `/?tour`
- `ret/` — эмбеддинги, разметка учителем, индексы, сравнение кандгенов, дообучение двухбашенного энкодера и SigLIP
- `rank/` — дообучение кросс-энкодера; `verify/` — данные и оценка QA-постфильтра; `train/` — SFT маленького оркестратора
- `eval/` — бенчмарки: одиночные запросы и 24 сценарных диалога; `eval/build_showcase.py` собирает данные для `/metrics`
- `deploy/` — развёртывание на VM с одной A100: `setup.sh`, быстрые загрузки колёс и моделей, восстановление дообученных LLM из дельт

Модели и эмбеддинги в репозиторий не входят.
